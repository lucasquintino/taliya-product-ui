# Spec Kit clarify

## Purpose

Resolve ambiguity before a feature is specified or implemented.

## Procedure

1. Extract ambiguity from requirements, scenarios, contracts, and dependency boundaries.
2. Ask only questions that change acceptance criteria, risk, sequencing, or ownership.
3. Record each answer as a numbered decision with rationale and affected artifacts.
4. Do not invent product behavior, dependencies, or authorization.

## Stop condition

Do not proceed to plan or implementation while a decision that changes a gate, public contract, security boundary, or data model remains unanswered.
