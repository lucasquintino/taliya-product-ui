# Spec Kit specify

## Purpose

Write a testable feature specification before implementation.

## Required content

- User stories and independent tests.
- Functional requirements with stable IDs.
- Scenarios covering success, empty, loading, error, permission, accessibility, security, and performance behavior where applicable.
- Non-functional constraints, package ownership, public contracts, and measurable success criteria.

## Rules

Use domain language, avoid prescribing internals without a contract, and mark uncertainty for clarification. Do not include implementation steps in the specification.
